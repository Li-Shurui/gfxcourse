# 第 0 课　把像素写成文件

## 这一课的目标

从一块纯内存开始：宽、高，和每个像素的红、绿、蓝。你用两重循环把颜色写进去，再把它变成一张能打开的图片。渲染器后面所有课，最后都还是在做同一件事，只是「每个像素该是什么颜色」这个问题会越答越长。

这一课不画三角形，也不碰三维。你只需要知道：内存里怎么排像素，以及像素怎么写成文件。

## 你会看到什么

运行之后，`output/` 里会多出两个文件，内容是同一张 320×320 的图：

- `00_image.bmp`，用 Windows 的照片查看器或画图就能打开。
- `00_image.ppm`，用文本编辑器也能看懂它的开头。

画面是从左上到右下缓慢变色的背景，中间有一块更亮的圆盘。左上角和正中心的颜色必须不一样，否则程序会报错退出，因为说明渐变没画出来。

## 帧缓冲：内存里的图片

代码里叫 `Image` 的东西，本质上是一块数组。宽是 `width`，高是 `height`，每个像素占三个字节。像素 `(x, y)` 的下标是 `y * width + x`。

`put` 和 `get` 的 `y = 0` 在图片最上面，`y` 越大越往下。这和数学课本里「y 朝上」的习惯相反，但和几乎所有图像文件、窗口系统一致。现在先记住这个约定，第 5 课投影到屏幕时会少一次符号错误。

`Color` 是三个 0 到 255 的整数。这一课直接写整数。从第 6 课开始，光照会先在 0 到 1 的浮点数里算完，临写出时才编码成整数。

## BMP 和 PPM：内存怎么变成文件

课程同时写两种格式，是为了让你看见「像素数组」和「文件里的字节」不是一回事。

PPM 是最容易读的格式。开头三行是魔数、宽高、最大通道值 255，后面就是每个像素的红绿蓝。程序写完 PPM 会立刻读回来，和内存里的中心像素比较，确认没有写反或写丢。

BMP 只写最常见的无压缩 24 位图：文件头 14 字节，信息头 40 字节，然后是像素。有三件事容易出错：

- 通道顺序是蓝、绿、红，不是红、绿、蓝。
- 每一行像素的字节数要补到 4 的倍数，补出来的字节没有意义。
- 文件里的第一行像素，是图像的最下面一行。内存里 `y = 0` 在最上面，写出时要倒着走。

这些都写在 `image.hpp` 的 `write_bmp` 里。数值按小端字节序手工放进头部，没有调用系统的图像库。BMP 就是这么定义的。

## 圆盘是怎么来的

对每个像素，先把坐标归一化到 0 到 1 之间，再量它到画面中心的距离。距离越小，颜色越亮。这还不是光线追踪，没有射线，也没有求交。它只是问：这个像素离某个位置有多远。第 11 课的射线会再问同一类问题。

## 跟着代码走

建议按这个顺序看：

1. `main.cpp` 的两重循环，只看它怎么调用 `Image::put`。
2. `image.hpp`，看 `put`、`get`，再看 `write_bmp` 和 `write_ppm`。
3. `paths.hpp` 的 `output_file`，它把文件名接到仓库的 `output/` 下面。所以你可以在 `build/` 里运行，图也不会写进构建目录。

打印用的是 `log.hpp` 的 `say` 和 `say_error`。它们用 `std::format` 拼字符串，再用 iostream 打出来。标准库的 `std::print` 在一些 MinGW 版本上链接不上，所以全课都走这两个函数。

`console.cpp` 只在 Windows 上有用：启动时把控制台设成 UTF-8，不然中文会乱码。它没有别的逻辑。

## 自己跑一次

在仓库根目录执行：

```powershell
.\build\lesson00.exe
```

用图片查看器打开 `output/00_image.bmp`。再用文本编辑器打开 `output/00_image.ppm` 的前几行，确认你能读懂文件头。

## 这一课没有做什么

没有直线，没有三角形，没有三维。颜色是手写进循环的。下一课补上后面所有几何都要用的向量。
