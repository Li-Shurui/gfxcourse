# 第 0 课　把像素写成文件

渲染器在这一课还不会画三角形。它只有一块内存：宽、高，以及每个像素的红、绿、蓝。你用两重循环把颜色写进去，再把这块内存变成别人能打开的文件。后面每一课都还是在填同一块内存，只是填色的理由越来越长。

## 你应该看到什么

运行后，`output/00_image.bmp` 和 `output/00_image.ppm` 是同一张 320×320 的图：背景从左上到右下缓慢变色，中间有一块更亮的圆盘。圆盘的边缘是距离场，不是以后的反走样。左上角和正中心的颜色必须不同，否则程序会报错退出。

## 帧缓冲

`Image` 把像素排成一行接一行的数组，索引是 `y * width + x`。`put` / `get` 的 y = 0 在图片顶端。这和数学课本里 y 朝上的习惯相反，和几乎所有图像文件、窗口系统一致。现在就把这个约定记住，第 5 课投影时少一次符号错误。

`Color` 的三个通道是 0 到 255 的整数。这一课直接写整数。从第 6 课起，光照先在 0 到 1 的线性浮点里算完，临写出时才编码成整数。

## BMP 和 PPM

课程同时写两种格式，是为了让你看见「像素数组」和「文件里的字节」不是一回事。

PPM 是文本或裸字节都能读懂的格式。P3 把每个通道写成十进制数字，P6 把它们紧挨着写成字节。文件头只有三样东西：魔数、宽高、最大通道值 255。`read_ppm` 两种都认。程序写完 PPM 会立刻读回来，和内存里的中心像素比较。

BMP 这里只写一种最常见的无压缩 24 位图：文件头 14 字节，信息头 40 字节，然后是像素。需要自己处理的有三件：

- 通道顺序是蓝、绿、红，不是红、绿、蓝。
- 每一行的字节数补到 4 的倍数，补出来的字节没有意义。
- 文件里的第一行像素是图像的最底下一行。内存里 y = 0 在顶端，写出时要倒着走。

这些都写在 `image.hpp` 的 `write_bmp` 里，没有调用系统的图像库。数值按小端字节序手工放进头部。个人计算机上的 BMP 就是这个约定。

## 圆盘

对每个像素，把坐标归一化到 0…1，再量它到画面中心的距离。距离越小，颜色越亮。这还不是光线追踪：没有射线，没有碰撞，只有「这个像素离某个位置有多远」。第 11 课的射线会从相机出发，问的是同一类问题。

## 跟着代码走

从 `main.cpp` 开始。循环里只调用 `Image::put`。写出文件时进入 `image.hpp`。`paths.hpp` 的 `output_file` 把文件名接到仓库的 `output/` 下面，所以你在 `build/` 里运行，图也不会写进构建目录。

`log.hpp` 的 `say` / `say_error` 用 `std::format` 拼字符串，再用 iostream 打出来。标准库的 `std::print` 在部分 MinGW 发行版上链接失败（缺终端支持的符号），所以全课都走这两个函数。

`console.cpp` 在 Windows 上于启动时把控制台代码页设成 UTF-8。它没有别的逻辑，并且会被链进后面每一课。

## 运行

```powershell
.\build\lesson00.exe
```

用系统图片查看器打开 `output/00_image.bmp`。再用文本编辑器打开同名 `.ppm` 的前几行，确认你能读懂文件头。

## 这一课留下的限制

没有直线，没有三角形，没有三维。颜色是手写进循环的。下一课补上后面所有几何都要用的向量。
