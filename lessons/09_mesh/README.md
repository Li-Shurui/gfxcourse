# 第 9 课　网格

立方体和球不必再在代码里写死。这一课读 Wavefront OBJ：顶点、纹理坐标、法线、面，以及面上的 `usemtl`。读进来的三角形走第 7 课的光照和第 6 课的光栅化。

## 你应该看到什么

`output/09_mesh.bmp` 上有四个模型：一个立方体、一颗球、一个环面，以及一块平面。它们来自 `assets/meshes/` 里的 `cube.obj`、`sphere.obj`、`torus.obj` 和 `plane.obj`。立方体应当有棱角，球和环面是光滑着色，平面铺在下面。

程序会检查立方体正好是 12 个三角形。平面的加载结果先放进变量再检查，不要在 `if` 的条件里解引用 `std::expected`。失败时那样写会抛异常，而不是走进你准备好的错误信息。

## OBJ 里用到的子集

解析器认识这些记录：

- `v` 顶点位置
- `vt` 纹理坐标
- `vn` 法线
- `usemtl` 从这一行起，后面的面使用这个材质名
- `f` 面。支持 `v`、`v/vt`、`v//vn`、`v/vt/vn`，也支持负索引

多于三条边的面扇形三角化：`(0,1,2)`、`(0,2,3)`、……。四边面因此得到两个三角形。凹多边形会错，课程的模型不用凹多边形。

索引在文件里从 1 开始。负索引表示从当前位置往回数，OBJ 允许边读边用。

同一个几何顶点可以对应不同的法线。立方体的角就是这样：三个面在空间里共用一个点，着色时却要三条法线，否则棱会被平滑掉。加载器的键是 `(v, vt, vn)` 三元组，不是只有 `v`。

缺法线的面会在加载结束时，用三角形的叉积累加，再归一化。球和环面的文件里写了法线；你自己导出的模型如果没有 `vn`，仍然能被照亮。

`load_obj` 在内部捕获解析异常，转成 `std::expected` 的错误字符串。调用方只看返回值。

## 模型长什么样

这些 OBJ 由 `tools/make_assets.cpp` 生成，单位和朝向是课程约定的一部分：

- 立方体是 `[-1, 1]³`，每个面法线为常数。
- 平面在 y = 0，xz 范围是 `[-1, 1]`，uv 从 0 到 4，所以一张贴图会重复。法线朝 +y。
- 球是经纬线网格。
- 环面的主半径约 0.52，管半径约 0.18。从侧面看，中间的洞是几何，不是深度错误。

场景里的 `mesh` 变换是 `T * Ry * S`，作用在这些局部坐标上。把立方体的缩放设成 0.5，世界空间的边长就是 1。

## 跟着代码走

`mesh.hpp` 的 `Vertex`、`Surface`、`Mesh`、`load_obj`。`main.cpp` 加载四个文件并画出来。光滑模型和立方体的差别只来自法线，着色器没有变。

## 运行

```powershell
.\build\lesson09.exe
```

用文本编辑器打开 `assets/meshes/cube.obj`，找到一个角上的三个面，看它们的 `v` 索引相同、`vn` 索引不同。再运行程序，确认这个角在画面上是硬边。
