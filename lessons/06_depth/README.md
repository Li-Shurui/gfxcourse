# 第 6 课　深度与裁剪

线框不管谁挡住谁。这一课给每个像素一个深度值，只留下更近的那一次写入，并在填三角形之前把视锥体外的部分切掉。颜色从这里开始在线性空间计算，写出时再编码成 sRGB。

## 你应该看到什么

`output/06_depth.bmp` 里有两个四边形。近处的是红色，远处的是蓝色。红的盖住蓝的中间。红的四周仍然能看见蓝。如果整张图都是蓝的，深度比较的方向反了；如果中心不是红的，近平面一侧的四边形没有画上，或者测试读错了编码后的颜色。

程序数过蓝色像素，太少也会失败。只靠「中心是红的」发现不了蓝色根本没画。

## 深度缓冲

`DepthBuffer` 用 `+∞` 清空。深度小的更近。测试是严格小于：相等时保留先写入的那个。窗口深度来自 NDC 的 z，在三角形里按屏幕重心坐标做仿射插值。它不需要透视校正。透视校正是给颜色、法线、纹理坐标用的。

第 5 课的问题可以在这里落地。裁剪空间的 z 和 w 一起变，直接比较 z 没有意义。除以 w 之后，NDC 的 z 在一条视线上单调变化，所以能当深度。它在近处变化快、远处变化慢，这是透视本身的形状，不是插值写错了。

## 视锥裁剪

一个三角形和近平面相交时，不能只丢弃在后面的顶点。丢弃会留下一个洞，或者让除法产生飞出去的像素。`clip_frustum` 在裁剪空间里对六个平面做 Sutherland–Hodgman：`x = ±w`、`y = ±w`、`z = ±w`。裁完的多边形是一个凸多边形，再从第一个顶点扇形拆成三角形。

在裁剪空间里对顶点属性做线性插值是合法的。位置、法线、颜色、uv 都挂在 `ClipVert` 上，和位置一起被切开。透视除法发生在这之后。

## 透视校正

屏幕空间的重心坐标不能直接混合世界坐标或 uv。一条在世界上等分的边，投到屏幕上后，近的一半占更多像素。正确的做法是插值「属性 / w」，再除以插值出来的 `1/w`：

```text
attr = (w0 * a0 / w0_clip + w1 * a1 / w1_clip + w2 * a2 / w2_clip)
     / (w0 / w0_clip + w1 / w1_clip + w2 / w2_clip)
```

代码里这个除数就是 `Varying::inv_w`。`perspective_interpolate` 把它写清楚了。深度不走这条路，走仿射的窗口 z。

法线插值之后要重新归一化。两个单位向量的平均一般不是单位向量。

## 线性颜色与 sRGB

`color.hpp` 实现 IEC 的 sRGB 传输函数，不是 `pow(c, 1/2.2)`。两者在中间调很接近，在接近 0 的地方不一样。着色器返回线性 `Vec3`，`write_linear` 负责编码。

这一课的红是线性 `(0.95, 0.22, 0.18)`。编码之后绿通道大约是 129，不是一个很小的数。测试比较的是 `linear_to_color` 的结果。如果你用「绿通道小于 80」判断是不是纯红，测试会在一张正确的图上失败。

## 跟着代码走

`raster.hpp` 的顺序是：`ClipVert`、六个平面的裁剪、`to_varying`、`rasterize_triangle`、`draw_clipped_triangle`。`rasterize_triangle` 复用第 3 课的边函数和 top-left 规则，在通过深度测试之后才调用着色器。

`main.cpp` 放了两个和视线垂直的四边形。近的 z 更大（没那么负），所以更靠近放在 +z 的相机。

## 运行

```powershell
.\build\lesson06.exe
```

把两个四边形的 z 对调再运行。中心应该变成蓝色，红色退到后面。深度缓冲不用改。

## 这一课留下的限制

着色器只返回你写死的颜色。下一课让它根据法线和灯光计算。
